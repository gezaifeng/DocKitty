## 验收约束

所有写入测试只使用独立临时数据。原论文和现有用户文档库不作为测试对象。已确认的项目来源删除规则、普通刷新规则、版本唯一分支归属不擅自改变。若测试揭示新的实际缺陷，追加到本清单并修复；未来产品构想与当前缺陷分别记录。

## 本轮界面与实际缺陷

- 右栏：版本常用操作固定在上方，信息 / 操作分区滚动；整份文档的编辑分支设置与所选版本分开。项目区按预览 / 信息 / 关系组织，原文件与快照身份明确。11 主题、1000×700 与 1440×1000 窗口检查已通过，证据位于 `fix-audit-0.5.13/inspector-mcp`。
- 项目导入后偶发退回首页：修复用过期项目列表校验新项目的时序；导入期间不清空有效选择。跨文件夹跳转也保留目标选择。
- DOCX 比较：损坏 ZIP、缺正文、非法 XML 明确报错；实体、段落、制表和换行正确提取。大文本与差异计算有界限，不长时间阻塞。
- 备份 / 恢复：校验完整引用链与项目文件对象；先恢复至临时目录，验证成功后整体发布。文件夹切换整体准备、整体替换；两个实际子进程定点强杀后恢复原工作区通过。
- 大文件：常规导入、还原、导出及备份不再收集全量文件；内置预览限额 20 MiB，超限统计仅展示已知信息，缺失指标不填零。

## 后续开发方向

1. 优先扩展真实使用规模：数百文稿 / 大项目的启动、刷新与关系图性能；按实测瓶颈做增量刷新、搜索和可见卡片渲染。

3. 把常用论文 / 项目流程做成可选择的模板，例如初稿、导师审阅、投稿资料；不自动改写原目录或偷偷创建迭代。
4. 完善 Agent 操作可见性：在桌面定位最近 MCP 改动、显示操作对象和结果，保持版本副本与项目原文件的区别。
5. 继续维护 Office / WPS 客户端样本与独立 Windows 安装矩阵，再考虑云同步、多人协作等新范围。
