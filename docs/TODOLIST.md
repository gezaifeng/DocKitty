## 第一阶段：P0 数据保护

- [ ] **P0-01 编辑入口只打开现有工作区文件。** 修改 `docHandlers.ts`，去掉编辑前无条件检出；文件缺失时给出明确恢复路径。验收：v1→v2→恢复v1→编辑仍为v1；未提交修改在再次编辑、重启后不被覆盖；补实际 handler 回归测试。
- [ ] **P0-02 恢复和分支切换保护未提交内容。** 在核心提供工作区变化检查，GUI 提供先提交 / 保存保护副本 / 取消的流程，CLI 同样不能绕过保护。验收：修改未提交时恢复、切换均不会静默丢稿；文件占用或恢复失败时原工作区仍可取回。
- [ ] **P0-03 修复目录纯删除及空目录快照。** 比较新旧 tree 的路径集合，记录删除；定义删光文档文件时的版本行为。验收：仅删除 b.txt 生成新提交，旧版本恢复包含 b.txt，新版本不含；嵌套删除、空目录政策有明确测试。
- [ ] **P0-04 禁止分支内部保留名及 Windows 冲突名。** 禁止 HEAD、路径逃逸、设备保留名，处理大小写冲突；按中文用户场景支持合法中文分支。验收：HEAD 被拒绝且原历史不变；中文“大修版”可创建和切换；大小写重名不会改写旧分支。
- [ ] **P0-05 消除大文件全量缓存并扩展验证。** `ingest/index.ts` 超过 64 MiB 后仍收集和合并全部字节；通用文件应真正流式摄取，恢复也避免全量常驻内存。当前 68 MiB 样例哈希往返通过，未确认数据损坏；这里针对内存耗尽风险。验收：64 MiB 两侧及更大、多块不同内容文件 SHA-256 往返一致；记录峰值内存与耗时，不以高重复零字节单一样例验收。
- [ ] **P0-06 明确并实现 OOXML 保真契约。** 优先满足用户完整保留历史文件的目标；决定原始包字节保留或可精确重建方案。验收：真实 Word/WPS/Excel/PowerPoint 文件逐版本恢复；若承诺逐字节一致，原始和恢复 SHA-256 必须相同；文件仍能被 Office 正常打开。
- [ ] **P0-07 提交与分支切换串行、失败一致。** 防多进程同库写入和同文档并发提交；切换失败回滚 HEAD / 工作区或保留可恢复状态；提交时固定读取快照。验收：双开仓库、重复点击提交、保存中提交、切换中写入失败不会丢历史或留下假分支状态。
- [ ] **P0-08 备份恢复不覆盖现有内容，路径受限。** 限制解压文件在目标根内，校验清单与实际包文件一致；禁止往非空目标直接恢复，先临时恢复验证再落地。验收：非空目录、`../`、绝对路径、不在清单中的文件、损坏包、失败中断均不会改动目标外文件或现有仓库。
- [ ] **P0-09 备份输出原子且来自一致快照。** 禁止输出到仓库内部；备份失败不能覆盖已有好备份；提交、删除分支时的备份保持可恢复。验收：故障注入后旧备份仍通过验证；并发备份恢复得到完整引用链和工作区状态；大仓库内存占用有记录。
- [ ] **P0-10 回收区恢复不覆盖同名新分支。** 检查同名冲突并允许恢复为新名称；删除当前分支被拒绝时不得产生假回收记录。验收：删除 review→重建 review→恢复旧 review，两个历史都能保留；失败删除不新增回收项。

阶段验收：用户反复编辑、恢复、切换和备份时，当前草稿与已提交历史均有明确保护；上述每个已复现问题都有回归测试。

- [ ] **P1-02 历史版本另存副本 / 用系统应用只读查看。** 直接导出某提交，不需要先覆盖工作区；无内置预览的文件也可查看副本。验收：导出十个历史版本，与其存储契约匹配；现有文件不被静默覆盖。
- [ ] **P1-03 接通双版本对比。** 时间线选择两个提交并渲染现有 DiffView；标明方向与版本信息。验收：GUI 可完成选择、比较、退出；错误和不支持格式有明确提示；绝不把解析失败显示成“无差异”。
- [ ] **P1-04 改善 DOCX 文本提取。** 使用可靠 XML 解析保留段落、制表、换行和实体；明确表格、页眉脚注、修订等覆盖范围。验收：中文、`&`、多段落、表格、删除修订样例有预期结果；正文删改不会被吞掉。
- [ ] **P1-05 完善 xlsx 预览和单元格比较。** 工作表选择、保留行列位置、明确公式与显示值；按工作表和坐标比较增删改。验收：多表、空行空列、公式、日期、合并单元格有可理解结果；无法高保真显示的部分明确说明。
- [ ] **P1-06 校正旧式 doc/xls/ppt 的支持边界。** 先移除错误的 xls→xlsx 解析；提供系统应用查看副本；确有需求再添加专门解析器。验收：真实 xls 不再被当成 xlsx；导入、恢复的字节一致；文档中分别列明保存 / 预览 / 比较能力。
- [ ] **P1-07 补齐分支操作入口。** 历史节点“从此创建分支”、创建后明确是否切换、非当前分支删除及回收区恢复。验收：导师大改和主线写作可独立提交；恢复指定起点正确；界面行为与教程一致。
- [ ] **P1-08 保存监听不漏掉待提交文档。** 监听整个受管工作区或管理多个 watcher；覆盖 Office 原子替换式保存；待提交文档按文档记录；重启扫描未提交变化；提供手动提交入口。验收：同时编辑两份文件、资源管理器启动、忽略提示、关闭再启动，都能找到未提交变化；程序检出不误报为用户新保存。
- [ ] **P1-09 统一刷新状态与错误反馈。** 切换分支刷新时间线和预览；保存、恢复刷新预览；备份恢复同步前后端仓库及缓存；关键失败展示可操作信息。验收：两个内容明显不同的分支切换后，分支名、时间线、预览一致；恢复新仓库后全部面板切换到新库。
- [ ] **P1-10 添加正常切换仓库入口。** 打开 / 关闭 / 最近仓库；切换前处理待提交内容，清理旧 watcher 和缓存。验收：不移动或改名仓库也能切换；没有串库预览、历史或保存通知。
- [ ] **P1-11 校正统计含义。** 分开工作区占用、历史对象占用、当前分支版本数、跨分支唯一提交数；需要节省比例时使用可解释的全量基准。验收：同一提交被多分支引用不重复计数；界面数字和实际目录字节数的差异有明确范围。

阶段验收：真实论文至少 10 个版本，完成“继续写当前稿→查阅旧稿→另存旧稿→比较两版→导师修改分支→回主线”的完整操作；查阅不会覆盖当前稿。
