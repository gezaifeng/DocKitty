# word_git 项目现状梳理

梳理日期：2026-10-10。对象：当前设备上的 `word_git` 源码，基线提交 `63f1419`。本文保留最初审计快照；随后已实施统一工作台和数据保护改动，最新功能与验证见 [第一可用版-产品与验收](第一可用版-产品与验收.md) 和 [使用教程](使用教程.md)。下文中的“尚未实现”指原始基线，不代表当前工作树。

## 1. 项目目前处于什么阶段

**已具备可运行、可构建的本地文档版本管理原型，但尚未达到适合放心托管论文唯一副本的成熟版本。** 核心版本存储和桌面主体已经实现；当前主要短板是工作区保护、历史查阅流程、真实 Office 兼容验证和发布验证。

你的需求包含两件事：一是保存多次迭代的完整历史，二是不打断当前写作就能查阅旧稿。项目对第一件事已有较多实现，对第二件事还缺关键交互。下一阶段应优先修复会覆盖稿件的问题，再接通旧版预览、导出和比较。

没有给出完成百分比：设计中的功能、实际实现的功能、已经验收的功能差异较大，简单百分比容易掩盖关键风险。

## 2. 架构与已经完成的内容

工程为 pnpm monorepo，使用 TypeScript；桌面为 Electron + React。核心无需依赖 Electron，也有独立 CLI。这里的“Git 式”表示借鉴提交、分支和检出语义；项目使用自己的 `.wg` 仓库存储格式，并非把 Office 文件交给真实 Git 管理。

| 模块 | 已实现内容 | 当前边界 / 主要证据 |
|---|---|---|
| 仓库 | 创建、打开、格式版本检查；对象、引用、工作区等目录；记忆上次仓库 | `packages/core/src/repo.ts`；旧格式迁移仍只是报错提示，`repo.yaml` 实际写 JSON |
| 导入 | 复制源文件到工作区，自动生成首个版本；核心还支持目录文档 | `ops.ts`；GUI 只提供文件选择，不能导入整个资料目录 |
| 提交与历史 | 按文档独立提交；提交说明、作者、时间、父提交；无变化不新增版本 | `ops.ts`、`model.ts`；目录仅删除文件的变化存在遗漏，见下文 |
| 历史恢复 | 从提交重建文件到工作区，目录检出可清理多余文件 | `ops.ts`；直接覆盖工作区，没有未提交内容保护 |
| 分支 | 从当前或指定提交创建分支；切换分支；删除分支与还原 API | `ops.ts`、`quarantine.ts`；GUI 只有创建和切换入口；创建不会自动切换 |
| 内容去重 | SHA-256 内容寻址、压缩对象、CDC 分块、相同文件复用、OOXML 部件复用 | `objectStore.ts`、`chunker.ts`、`ingest/`；有合成文档 50 版去重测试，不能代表所有真实文件 |
| 基础可靠性 | 对象和引用使用临时文件、fsync、rename；提交日志；启动清理残留 | `fsutil.ts`、`journal.ts`；日志恢复是清理残留，不是完整事务重放或回滚 |
| 自检与备份 | 对象哈希检查；含逐文件校验清单的 ZIP 备份及恢复 | `scrub.ts`、`backup.ts`；自检不等于所有历史可恢复；备份尚缺一致快照及目标保护 |
| 桌面流程 | 首次建库/打开、文档卡片、时间线、编辑入口、保存后提交卡、快捷说明 | `apps/desktop/src/`；保存监听和工作区管理还不完整 |
| 预览 | docx-preview；ExcelJS 读取 xlsx 后渲染表格 | 预览当前工作区；xlsx 只展示第一张表的简化内容；doc/xls/ppt/pptx 的能力需分开说明 |
| 对比 | DOCX 正文提取、字符级增删 diff、DiffView 组件及单测 | `diff.ts`、`commitHandlers.ts`、`DiffView.tsx`；没有主界面入口，没有表格单元格对比 |
| 设置和外观 | 存储统计、备份、自检、回收区恢复；中文界面、主题切换和动效 | 统计只累计各文档当前分支历史，字节数只计对象目录；不是全仓库占用或全分支版本总数 |
| CLI | init / import / commit / log / checkout / branch | `packages/cli/src/index.ts`；尚无完整维护命令，也没有独立发布的 CLI 安装入口 |
| 打包 | electron-builder 的 Windows NSIS 配置、应用图标、生产构建 | 本设备初始源码中没有教程所称的安装包；本次未生成或验收安装包 |

## 3. 办公格式支持的实际范围

“能保存版本”与“能预览或比较内容”是不同能力。

| 格式 | 存储路线 | 内置预览 | 内容对比 |
|---|---|---|---|
| `.docx` | OOXML 部件去重 | 已实现当前工作区预览，复杂排版未经真实 Office 验收 | 正文字符 diff 已实现，尚未接入完整 GUI 流程 |
| `.xlsx` | OOXML 部件去重 | 第一张工作表的简化表格 | 未实现单元格 diff |
| `.pptx` | OOXML 部件去重 | 无 | 无 |
| `.doc` / `.xls` / `.ppt` | 通用二进制分块 | `.doc`、`.ppt` 无；`.xls` 被错误送入 xlsx 解析器 | 无 |
| PDF、图片、其他文件 | 通用分块 | 无专门预览 | 无 |
| 论文 + 配图等目录 | 核心支持目录快照 | GUI 未提供目录管理或内部文件选择 | 没有目录比较流程 |

上述存储路线由代码确认，不代表每种格式已经用真实文件完成恢复和 Office 打开验收。对于 `.xls`，界面条件和教程宣称支持，但 `XlsxPreview` 调用的是 `workbook.xlsx.load`，不能据此认定支持旧式二进制 Excel。

## 4. 已确认的关键问题

### 4.1 点击“编辑”会覆盖未提交内容，也会撤销刚恢复的旧稿

`apps/desktop/src/main/ipc/docHandlers.ts` 中，`editDoc` 先执行默认 `checkoutDoc`，再用系统程序打开。默认检出的是当前分支最新提交，而不是单纯打开现有工作区。

本次在临时仓库复现了相同核心调用链：提交 v1、v2 → 恢复 v1 → 执行编辑入口中的默认检出 → 文件变回 v2。另一个实验中，未提交文字也被 v2 覆盖。未调用真实 Word，但覆盖行为已在实际磁盘文件上确认。

这同时意味着教程的“恢复旧版本后点编辑查看”和“编辑只是打开当前工作区文件”与代码不符。应首先让编辑入口只打开文件；需要重建缺失文件时单独处理，并在所有覆盖操作前检查工作区状态。

### 4.2 恢复与切换分支缺少保护，切换失败可能留下不一致状态

时间线恢复和分支切换直接执行 API，无未提交检查、自动保护副本或确认流程。`switchBranch` 先写当前分支 HEAD，再检出文件；检出失败时没有回滚，界面所示分支与工作区可能不一致。目录检出逐文件执行，单文件原子替换不代表整个目录事务原子完成。

### 4.3 目录中只删除文件，提交会误认为“无变化”

`commitDoc` 只遍历仍存在的路径；删除的路径没有加入 `changed`。本次导入含 a.txt、b.txt 的目录，删除 b.txt 后提交，返回 `commitId: null`、`changed: []`。删除最后一个文件还会触发“文档为空”错误。目录型论文资料的版本语义需要补齐。

### 4.4 OOXML 保存的是解包内容，不能保证原文件逐字节还原

`encodeOoxml` 没有记录原 ZIP 时间戳、压缩方式等完整元数据；`decodeOoxml` 重新压缩并统一时间戳。本次用不同时间戳和压缩方式生成 DOCX 包，导入、检出后 SHA-256 不同。

这不证明正文丢失，也不证明文件无法打开；它证明“任何原文件逐字节还原”的承诺不成立。现有 50 版本测试的合成输入恰好适配重建方式，不能替代真实 Word/WPS 文件验证。需要明确产品承诺：若要求原文件完整保真，就必须保存能重建原始包的信息，或保留原始字节。

### 4.5 分支名允许 `HEAD`，会与内部元数据冲突

`createBranch` 的正则允许大写 `HEAD`，而 `refs.ts` 用同名文件保存当前分支名。本次创建此分支后，默认历史查询从原本存在的历史变成空数组。还需要覆盖 Windows 保留名、大小写重名、路径字符等规则。设计和教程中的“大修版”等中文分支名目前也会被正则拒绝。

## 5. 有实现但尚未形成完整用户能力的部分

- **旧版只读预览**：预览 IPC 可接收 commitId，但界面只请求当前工作区；时间线没有选择某版供预览的状态和入口。
- **差异比较**：DiffView 只被其测试引用，MainLayout 未渲染它，时间线也没有选取两个版本的入口。非 DOCX 被正文提取器处理时返回空字符串，可能表现为没有差异，应明确提示不支持。
- **正文提取**：使用正则删除 XML 标签，只读 `word/document.xml`；不保留段落结构，不完整处理 XML 实体、页眉页脚、脚注等，也不区分修订的语义。
- **另存旧版副本**：没有直接导出历史文件的入口。为了查一句旧稿而覆盖当前工作区，不符合主要使用场景。
- **分支管理**：底层支持历史起点和删除；GUI 缺“从此版本建分支”和删除入口。教程称创建即切换，但 GUI 和核心创建函数均不切换。
- **保存监听**：只有点击 App 内“编辑”后才启动，且全局只有一个 watcher，后打开的文档替换前一个监听；只订阅 change。直接在资源管理器打开、同时改多个文件、Office 临时文件替换式保存还需验证。提交提示只保存一个待处理文档，新的事件可覆盖旧事件。
- **界面刷新**：分支切换只刷新文档列表，没有刷新时间线和预览；恢复只刷新文档列表，预览缓存可能仍显示旧内容。备份恢复后只替换主进程仓库，前端仓库状态和缓存没有同步更新。
- **错误反馈**：部分操作报错只到 console，或把失败历史查询吞成空数组；设置页备份、自检等没有完整失败和恢复成功反馈。
- **切换仓库**：主界面缺少正常的关闭/打开另一仓库入口，教程建议移动仓库目录作为绕行办法。

## 6. 可靠性设计尚未落地或需要强化的内容

| 设计目标 | 当前情况 | 后续方向 |
|---|---|---|
| “任何情况下不丢失” | 有基础保护，但已存在未提交覆盖路径 | 改成可验证的故障范围与恢复规则，避免绝对承诺 |
| 完整事务恢复 | 日志记录操作基本信息，启动删除日志和部分 tmp | 覆盖导入、切换、检出、备份等故障；用明确阶段注入验证 |
| Office 占用检测 | 未找到锁文件检测与专门处理 | Word/WPS 正在保存或占用时，不覆盖、不提交半写文件 |
| 磁盘空间预检查 | 未找到实现 | 注入写满、权限、rename 失败，验证旧历史保持可读 |
| 多进程 / 并发写入保护 | 未找到仓库写锁或提交串行机制 | 防双开同库、GUI/CLI 同写、并发提交丢失分支更新 |
| 超大文件恒定内存 | `encodeFile` 先拼接全部字节；超过 64 MiB 后仍收集和合并；恢复及备份也整体入内存 | 修复真正的流式摄取与输出，并做大文件哈希回归 |
| 自检修复 | 校验现存对象，没有自动修复 | 验证 refs→commit→tree→manifest→chunk 链；发现缺失对象；提供恢复操作 |
| SQLite 派生索引 | 创建 index 目录，但未找到 SQLite 查询和重建实现 | 小规模可以继续遍历，不必为追设计而新增数据库 |
| 回收区 / GC | 回收条目保存分支引用；purge 只删条目，没有对象回收算法 | 防同名分支恢复覆盖；GC 可后置，先明确保留与清理语义 |
| 备份快照 | 遍历时未冻结仓库，整包入内存，直接写目标文件 | 写入时一致快照、原子输出；避免备份输出到仓库内部 |
| 备份恢复 | 校验清单后直接写目标，未阻止现有目录覆盖，也未限制 ZIP 路径到目标目录内 | 空目标/临时目录校验再落地；路径边界、清单范围、失败清理保护 |
| 格式迁移 | 版本检查已实现，迁移工具没有实现 | 真正升级存储格式时再设计迁移，迁移前备份 |
| 网盘同步冲突 | 未找到冲突副本识别 | 不把“单目录可复制”等同于支持实时同步并发 |

## 8. 建议的开发顺序

1. **先保住稿件**：修复编辑覆盖、危险操作保护、目录删除、分支元数据冲突；补齐大文件往返和备份恢复保护。
2. **再完成找旧稿的闭环**：时间线点选旧版只读预览、另存副本、双版本对比、刷新与保存监听。
3. **最后验收交付**：真实论文与表格语料、Word/WPS 保存实验、真实 Electron E2E、锁定开发环境、安装包验收和教程校正。

暂不扩展手机端、在线协作、自动合并、自研 Office 编辑器和加密。这些不是当前论文迭代场景的缺口。
