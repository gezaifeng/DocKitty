# 稿喵 0.5.1：项目文档库与 Agent 迭代管理

状态：0.5.1 本地构建已完成开发与验收。确认日期：2026-10-13。本文按已确认规则定义产品，不以旧讨论代替最终行为。本次验收证据见 [分类与方向连线验收](project-categories-audit/README.md)，原有项目功能记录见 [项目管理验收](project-audit/README.md)。

## 产品定义

稿喵是本地文档整理和迭代管理软件，提供左上角两个独立入口：

- **版本管理**：原有单文档版本、单一分支归属、分类、历史比较和量化统计。
- **项目管理**：把文件、文件夹与整轮迭代收进多个文档库，用有名称的关系整理资料。无需使用代码仓库或分析程序架构。

## 用户已确认的完整规则

1. 不持续监听原项目目录。软件启动时同步一次；MCP 修改后同步；其他修改由用户点击刷新。
2. 刷新更新当前卡片内容，不自动增加版本。用户或 MCP 明确记录迭代才保留旧内容并创建下一节点。
3. 来源删除会同步移除对应当前卡片、历史卡片及连线。来源改名视为删除旧路径、导入新路径。
4. 项目管理中“编辑原文件”打开真实来源文件。测试必须使用独立样例；原有版本管理仍使用独立编辑副本。
5. 批量导入多个文件或整个文件夹，可选择已有文档库或新建文档库。不自动排除 .git、node_modules 或构建输出。
6. 文件夹可作为一张卡片整体管理，也可将父文件夹的直接子项放入文档库。双击普通文件夹逐层进入；每层只画本层文件与子文件夹。
7. 允许跨文件夹关系。本层不绘制跨层连线；详情列出完整路径，点击跳入目标层并选中资料，清除筛选并定位目标。
8. 项目管理以可多选的文件类型筛选取代分支筛选；文件夹和任意格式均可保存，未知格式可导出。
9. HTML 只显示安全页面效果，不执行脚本，不加载外部网络，不提供源码切换。MD/PY/CPP/配置和常见脚本按文本查看，代码不会运行。
10. 软链接、目录联接只保留普通卡片及目标路径，不展开、不复制或打开目标。循环及失效链接也能记录；目标本身不纳入管理。
11. Agent 接入覆盖 Codex、Claude Code、Cursor 和 DSH。前三者提供自带运行环境的 stdio 配置；DSH 使用软件内开启的本机 Streamable HTTP 服务。

## 交互流程与数据规则

导入完成后，一个文档库拥有文件浏览、文件关系图与分类看板三个视图。节点包含唯一编号、原始名称、显示名称、备注、分类归属、类型、字节数、来源路径、记录时间、位置与快照状态。重名导入不覆盖其他卡片。显示名称、分类和备注不回写源文件名。

点击“连接资料”，依次选择两个节点，自由填写标签和备注，不提供关系类型选择；可按 Esc 或点击取消退出。两个文件夹、两个文件或文件与文件夹均可连接。箭头从起点指向目标；线条从卡片中心连接，位于卡片下层，方向箭头放在目标卡片外侧以保证可见。双击连线编辑起点、目标、标签和备注；删除连线保留两端节点。手工关系允许双向和循环；自动生成的迭代关系保留循环检查。自连接与跨库连接不允许。

分类名称由整个项目共用，分类看板只显示当前文件夹这一层资料。文件和文件夹均可分类，不连带改变子项。拖动卡片到分类列、详情选择或名称编辑可改变分类；归属同步到关系图与文件浏览标签。改名同步全项目；删除分类后资料回到未分类，不删除任何资料与关系。刷新保留分类，备份保存分类；新导入的资料默认未分类。

关系图支持鼠标滚轮围绕指针缩放、拖动空白平移、拖动卡片保存位置；详情栏可拖动分隔条调整宽度。切换浏览视图不改变资料、关系和备注。

**显式记录下一轮**保留上次已存入稿喵的内容为历史，再读取来源最新内容形成下一轮；文件夹同时保留完整树。后续刷新只更新当前节点，不改写已有历史；历史文件夹层不接受新的导入。应在来源改完之后、再次刷新之前记录；刷新已经覆盖的未记录内容无法事后找回。也可通过 MCP 导入独立的新一轮文件夹并指定前一轮编号。

**移除资料**只删除管理卡片、其子项和相关连线，来源保持不变。手动移除的来源加入排除记录，后续刷新不反复导入；重新显式导入仍可管理。来源路径的真实删除按用户选择同时移除历史。重要历史可事先导出。

HTML 允许已导入的相对 CSS/图片资源，不允许脚本、嵌入对象、外部网络或来源目录中未导入的资源。DOCX/XLSX 复用现有预览；其他文件保存原字节并提供导出。链接卡片只记录路径，没有目标快照；包含链接的文件夹导出会明确提示，应选择普通资料导出，不会跟随链接读取其他位置。

## 存储、兼容与安装

旧数据不迁移到新模型；两个入口使用同一软件文档库根位置但独立数据。项目目录 projects/catalog.json 与 objects/project-files 内容对象参与原有备份，目录层级、空目录、中文名称和关系持久保留。文件操作使用串行写锁、跨进程锁及原子索引替换，导入失败不提交一半卡片。

软件不在源目录写入隐藏元数据。导入和刷新只读来源；主动“编辑原文件”才打开来源编辑器。禁止把稿喵文档库或包含它的目录导入自身。未知程序文件不执行。

Windows x64 安装包包含运行环境和 MCP 服务，不要求用户安装 Node、Python、Git 或 pnpm。编辑办公文件需要用户已有 Word/WPS/Excel 等应用。安装版默认库位于用户数据目录；卸载不主动删除资料。旧版公开包保持可用，新版交付从无个人数据的干净构建生成。

## MCP

12 个工具：list_libraries、create_library、list_items、import_items、refresh_library、record_iteration、update_item、set_relation、remove_relation、remove_item、read_file、export_item（实际名称均带 dockitty_ 前缀）。

返回节点和关系编号。导入与记录支持 requestId：同参数重试不新增节点，同标识不同参数报错。MCP 和桌面共享持久数据，MCP 写入后刷新来源，桌面获取新状态，不需控制 UI。

stdio 使用软件自带运行环境，可在桌面关闭时运行。DSH 本机 HTTP 只绑定 127.0.0.1，需要 Bearer 密钥，拒绝未授权请求及浏览器来源；开关在“接入 Agent”内。开启后随软件启动恢复同一地址，关闭软件停止服务。操作只用于用户配置的同一文档库，不执行脚本。
