# 稿喵版本统计：候选指标与实现方案

2026-10-11。本轮为功能设计清单，尚未实现统计模块。根据当前源码核对：已保存分支指针、版本父子关系、创建时间、作者、分类、内容快照及覆盖次数；已有 DOCX、XLSX、PPTX 和文本格式的文本比较基础，但尚无专门的分支统计 API。

## 统计范围与交互

在版本管理视图增加“统计”入口，选择文档后选择分支。切换分支只改变统计范围，不切换实际编辑分支。默认沿分支头追溯父版本，包含共同祖先；可选择“仅分叉后”。若存在多父版本，需明确主线或全祖先口径，不能单纯按时间混排。回收版本默认不计入，允许显示但要标记。

横轴可选版本序号或软件记录时间；后一种不是原文档创作时间。可设起止版本、时间范围、基准版本。图表悬停显示实际值和变化量，点击节点定位版本，选中两点进入已有版本比较。导出 CSV 与 PNG 可作为后续选项。

## 指标清单

“已有数据”表示可从当前数据计算，不表示已有统计界面。“需解析”表示需要新增或改进内容分析。“需记录”表示要新增事件数据，历史记录无法完整补齐。

| 指标 | 计算方法 | 展示 | 实现条件 |
|---|---|---|---|
| 分支版本数、分叉后新增版本数 | 遍历版本父链、共同祖先去重 | 数字卡、路线标记 | 已有数据 |
| 首末记录时间、记录跨度 | 版本时间范围 | 日期卡、时间轴 | 已有数据 |
| 有保存记录的天数 | 按本地日期去重 | 日历热力图 | 已有数据 |
| 日/周/月保存次数 | 版本创建记录分桶 | 柱图、热力图 | 已有数据；不能算实际编辑次数 |
| 相邻记录间隔、平均/中位间隔 | 版本时间差 | 散点、数值卡 | 已有数据；不能算写作时长 |
| 分类分布、每类版本数量 | 分支版本的当前分类 | 横向条形图 | 已有数据；不是历史分类变化 |
| 作者标签分布 | 版本作者字段 | 条形图 | 已有数据；非身份验证与贡献归属 |
| 覆盖修订次数 | revisionCount 汇总 | 数字卡、节点徽标 | 已有数据；撤销后是当前保留的修订深度 |
| 分支共有/独有版本数、分叉深度 | 共同祖先与节点集合比较 | 双分支时间线 | 已有数据 |
| 文件体积、体积变化、增长率 | 历史副本字节长度及相邻差 | 折线、正负柱图 | 可从快照计算 |
| 相同内容版本数 | 内容ID，必要时规范化文本哈希 | 重复标记 | 可从快照计算；二进制相同与文本相同要分开 |
| 总字数、相邻字数差、累计净增长 | 统一字数规则，当前减前版或基准 | 折线、正负柱图 | 需解析 |
| 字符数、汉字数、英文词数、数字数 | Unicode分类、英文分词 | 分类条形图 | 需解析 |
| 新增量、删除量、总改动量 | 文本对齐；总改动=新增+删除 | 双向柱图、数值卡 | 可复用差异算法，需改善提取 |
| 修改强度 | (新增+删除)/(前后两版计数之和) | 百分比折线 | 需统一计数单位；两版皆空时不适用 |
| 文本保留率 | 对齐保留量/前版总量 | 保留与删除堆叠条 | 需解析；不是语义相似度 |
| 新增占比、删除占比 | 新增/后版总量、删除/前版总量 | 百分比条 | 需解析；空版分母不适用 |
| 重写热点、大改版本排行 | 按改动量或修改强度排序 | 标注节点、排行榜 | 需解析 |
| 相邻变化与基准变化 | 同时比较前版和指定基准 | 双列卡、叠线 | 需解析；累计新增不等于最终新增 |
| 段落、标题、章节数量 | 读取 DOCX 结构与标题样式 | 小折线、结构树 | 需结构解析 |
| 各章节字数、占比与变化 | 匹配标题ID/文本与章节区间 | 堆叠条、章节热力图 | 需结构解析；重命名可能需要手动确认 |
| 新增/删除/修改段落数量 | 段落哈希、序列对齐 | 堆叠柱图 | 需结构解析；段落移动单独标记 |
| 表格、图片、脚注、尾注、批注数量 | 读取对应OOXML部件与关系 | 图标卡、小折线 | DOCX需结构解析 |
| 批注未解决/已解决数量 | 可识别的批注状态 | 堆叠条 | 格式相关；无状态信息时只报总数 |
| 工作表数量与增删/重命名 | XLSX结构、工作表标识匹配 | 变化清单、折线 | 需表格解析 |
| 非空单元格数、有效行列数 | 忽略单纯格式，统计真实值 | 折线、数据卡 | 需表格解析；不直接使用最大格式化区域 |
| 新增/清空/改值单元格数 | 按表标识与地址或配置业务主键对齐 | 双向柱图、表格热力图 | 需表格解析；插行不能误算所有后续单元格 |
| 公式数量、新增/删除/改写公式数 | 比较公式表达式 | 柱图、单元格清单 | 需表格解析；公式与结果分别统计 |
| 指定数值列的合计/均值/极值 | 用户选择工作表、列和单位 | 折线、数值卡 | 需用户配置；不把无关数值相加 |
| 空值比例、错误值数量 | 明确表格有效范围与类型 | 质量卡、条形图 | 需表格解析；公式无缓存结果不当作错误 |
| 幻灯片数、文本量、备注量 | PPTX幻灯片和备注XML | 多指标折线 | 需结构解析 |
| 幻灯片新增/删除/修改数量 | 稳定标识与内容匹配 | 幻灯片时间线 | 需结构解析；换序与改内容分开 |
| 目标字数达成率、剩余量 | 用户目标与当前字数 | 进度条、目标线 | 需用户配置，不推断完成程度 |
| 覆盖、撤销、恢复等操作频率 | 事件发生时间与类型 | 活动时间线 | 需新增事件日志，仅记录启用后 |
| 实际编辑时长 | 明确会话计时、空闲暂停与授权范围 | 时长图 | 需额外计时；不建议第一版加入 |

## 关键统计口径

1. 推荐“字数”采用汉字逐字加英文单词计数，另列非空白字符数。新增/删除默认使用明确标注的“字符”单位；如要统计词级变化，应以同一分词器做差异，不能混用。说明是否计入标点、数字、表格、脚注。不要宣称与 Word/WPS 数字完全一致。
2. 示例：前版10000字、后版10200字，但可能新增1200字、删除1000字。净增200不等于只修改200。示例仅解释概念，实际新增/删除与字数必须采用一致单位才能相减。
3. 同一版本覆盖保存不新增折线节点，当前节点重新计算，并用覆盖次数徽标提示；需要时再展开保留的修订快照。当前保存的是内容ID历史，缺少完整操作时间，不能伪造逐次覆盖时间趋势。缓存按内容ID、解析器版本及统计规则区分。
4. DOCX当前提取仅剥离正文XML标签，不能可靠统计段落/标题，也没有充分处理转义、制表符、换行与其他部件。统计前应改为结构解析。解析失败显示“未能统计”，不能把空字符串当0字。
5. 表格现有文本比较包含工作表名、地址和JSON化值，不适合作为字数来源；要直接解析真实单元格值。移动行、插列、重命名工作表需要对齐，无法确定时显示不确定匹配。
6. DOC/XLS等旧二进制格式目前没有相同的内容统计基础。仍可报版本数、时间、文件大小；内容指标需增加兼容解析或用户转换为DOCX/XLSX。PDF需文本提取，扫描版需OCR；OCR指标必须标注估算。
7. 版面页数需实际排版引擎，文档属性中的页数可能陈旧；语义相似度需额外模型，不能把字符保留率称作语义相似度。当前不建议加入“内容质量”“真实贡献”“准确编辑时长”等缺乏数据依据的分数。

## 实现路线

主进程只读读取选定分支快照，构建版本序列，按格式提取结构，计算单版指标及相邻/基准差异，通过新的统计IPC返回数值与可用性状态。前端只负责筛选、图表与联动；点击统计节点沿用已有比较/预览功能。

首次打开后台计算并显示逐版进度，缺失数据不连成0点。缓存按文档内容ID、解析器版本、统计规则区分，覆盖保存后同一版本节点更新但缓存键不同。读取历史快照不切换工作区，不改文件。版本多时只优先计算可见范围与用户选定指标。

第一批建议：分支选择、字数折线、新增/删除/净变化/总改动、版本数、覆盖次数、记录活动热力图、文件大小、基准比较、点击图表定位版本。第二批：DOCX章节和段落热点；第三批：表格与演示文稿专项统计。

## 三种真正不同的视觉布局

| 方案 | 布局与阅读逻辑 | 视觉 | 实现 |
|---|---|---|---|
| A 写作手账 | 一条大字数曲线贯穿主区，节点附便签；右侧显示选中版本的新增/删除及章节摘要，活动日历置底 | 米白纸张、墨线、浅绿标注，猫咪小印章只做点缀，精确图表不做抖动线 | React布局 + 自定义SVG图表，可精确控制注释和点击联动 |
| B 统计工作台 | 顶部筛选与指标卡，中部字数/改动联动图，底部热力图与可排序版本明细；刷选区间驱动全页面 | 留白清晰、细网格、强调色与精确数字，密度较高 | Apache ECharts，适合多图、事件联动与区间缩放 |
| C 版本旅程 | 左侧纵向版本路线，中间按版本展开统计卡并串联迷你折线，右侧固定基准对比；以版本为入口逐步展开 | 编辑出版感、大版本编号、克制插画、章节式排版 | React + Recharts趋势组件 + 现有动效库，重在滚动阅读与节点展开 |

三者不是换色主题，导航入口、主次信息、排版与交互逻辑都不同。本轮只有实现方案，选择方向后再制作可交互视觉样稿。

官方能力参考：[ECharts事件与图表联动](https://echarts.apache.org/handbook/en/concepts/event/)、[坐标轴与缩放](https://echarts.apache.org/handbook/en/concepts/axis/)、[Recharts图表示例](https://recharts.github.io/en-US/examples/)。
